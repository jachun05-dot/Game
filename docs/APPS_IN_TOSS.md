# 앱인토스 출시 준비 (2026-10-28 조사)

출처: 앱인토스 개발자센터(developers-apps-in-toss.toss.im — `llms.txt`, `checklist/app-game.md`, `intro/guide.md`, `ai-vibe-coding/tutorials/webview.md`), 앱인토스 블로그. 정책은 수시로 바뀌므로 신청 직전에 다시 확인한다.

## 1. 사람이 해야 하는 일(코드 밖)

- 앱인토스 콘솔 워크스페이스·앱 등록(`appName` 확정 — 설정 파일과 같아야 업로드된다)
- 사업자등록, 게임제작업 등록(블로그 안내: 게임은 개인도 필요)
- **게임물관리위원회(GRAC) 등급분류 필수** — 앱스토어·구글플레이 IARC 등급은 국내에서 효력 없음. 약 10~15일
- `.ait` 업로드 → 테스트 앱스킴으로 실기기 확인 → 검수 요청(영업일 2~3일, 운영·기능·디자인·보안) → 출시하기

## 2. 콘텐츠 정책 — 이 게임의 가장 큰 위험

- 「만들 수 없는 콘텐츠」 불법·범죄 조장 항목: "미성년자 등장 콘텐츠는 즉시 삭제되고 신고돼요"
- 폭력성: 타격·고통 묘사·피 = 2단계(주의), 유혈·잔혹·학대·고문 = 3단계(출시 불가). 주의 단계여도 내부 심의로 출시 제한 가능
- 이 게임: 주인공 16~17세, 세금 미납 처형, 18세 처형, 머리·몸통 결손 즉사, "아동 사망·처형" 경고 문구
- → 토스판은 설정 조정이 필요할 가능성이 높다(결정 대기). 예: 나이 표현 제거·성인으로, 처형 → 추방, 잔혹 묘사 완화

## 3. 기술 체크리스트(게임 출시 가이드 중 이 게임에 해당하는 것)

| 항목 | 지금 | 할 일 |
|---|---|---|
| 10초 안에 첫 화면 | 정적 빌드, 가벼움 | 실기기 확인 |
| 우측 상단 닫기 버튼·Safe Area(다이내믹 아일랜드) | 웹 기준 레이아웃 | safe-area 여백 |
| 진입 즉시 바텀시트 금지 | 없음 | — |
| 사용자 식별키로 진행 유지, 재접속 시 데이터 유지 | localStorage | SDK 저장소/식별키로 저장 |
| 안드로이드 백버튼 = 뒤로가기 또는 종료 | 없음 | 백버튼 처리 |
| 종료 시 확인 모달 | 없음 | 추가 |
| 토스 도메인 밖 콘텐츠 렌더링 금지, SSR 금지 | Google Fonts 외부 CSS, CSR | 글꼴을 번들에 포함 |
| eval 등 외부 코드 실행 금지 | 없음 | — |
| 세로 모드 고정, 풀스크린 | 세로 레이아웃 | 설정 |
| 사운드 On/Off | 사운드 없음 | — |
| 인앱 결제·광고 | 없음 | 수익화 결정 후 |

## 4. 연동 절차(웹 프로젝트)

```sh
npm install @apps-in-toss/web-framework   # 2026-10 기준 3.9.0
npx ait init                              # apps-in-toss.config.ts 생성
```

```ts
import { defineConfig } from "@apps-in-toss/web-framework/config";
export default defineConfig({
  appName: "<콘솔에 등록한 이름>",
  brand: { primaryColor: "#…" },
  webView: {},
  permissions: [],
  webBundleDir: "dist",
});
```

- 비게임 미니앱은 TDS 필수, 게임은 체크리스트에 TDS 항목 없음
- 배포 API 키는 콘솔에서 발급(사용자 보관, 저장소에 넣지 않는다)
